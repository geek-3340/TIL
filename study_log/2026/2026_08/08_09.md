### 詳細・補足

**1.gitの開発フロー再確認**

ブランチを切って、PRを送るまでのフロー

```bash
# 1 リポジトリをクローン
git clone https://github.com/user/repo.git

# 2 プロジェクトフォルダに移動
cd repo

# 3 依存関係をインストール
npm install # 例

# 4 新しい作業ブランチを作成して切り替え
git switch -c feature/add-login

# 5 コードを編集（新機能などを実装）

# 6 変更をステージングしてコミット
git add .
git commit -m "Add login feature"

# 7 mainブランチへ切り替え、最新を取得
git switch main
git pull origin main

# 8 作業ブランチに戻る
git switch feature/add-login

# 9 最新mainの変更をmergeで取り込む
#    → 変更点を統合しつつ履歴も残る
git merge main

# （コンフリクトが出た場合）
#    1. 該当ファイルを修正
#    2. 修正後に以下を実行
git add .
git commit  # merge完了のコミットを作成

# 10 リモートへpush
git push origin feature/add-login

# 11 実装完了後、GithubにてPR作成
```

**2.gitのリモートとのコンフリクト解消について**

開発用ブランチからリモートへpushする際に以下のエラー

```bash
# pushを試みる
$ git push origin brc

# エラー要約：「却下、push失敗した、リモートにはローカルに無い変更がある、今度から先にpullしてから変更してくれ」見たいなことが書いてある
To https://github.com/user/my-app
 ! [rejected]        brc -> brc (fetch first)
error: failed to push some refs to 'https://github.com/user/my-app'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. This is usually caused by another repository pushing to
hint: the same ref. If you want to integrate the remote changes, use
hint: 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.

# こうなると通常のpullも通らない
$ git pull origin brc

remote: Counting objects: 100% (9/9), done.
remote: Compressing objects: 100% (4/4), done.
remote: Total 5 (delta 3), reused 0 (delta 0), pack-reused 0 (from 0)
Unpacking objects: 100% (5/5), 1.08 KiB | 34.00 KiB/s, done.
From https://github.com/user/my-app
 * branch            brc        -> FETCH_HEAD
   63c3c35..11bba59  brc        -> origin/brc
hint: You have divergent branches and need to specify how to reconcile them.
hint: You can do so by running one of the following commands sometime before
hint: your next pull:
hint: 
hint:   git config pull.rebase false  # merge
hint:   git config pull.rebase true   # rebase
hint:   git config pull.ff only       # fast-forward only

fatal: Need to specify how to reconcile divergent branches.
```

解決方法：rebase/no-rebaseでpullしてコンフリクトを解消する

> 今回はmergeする運用を前提に`no-rebase`を使用

```bash
# 以下のコマンドで該当ファイルにコンフリクト箇所が表示され編集できる
git pull --no-rebase origin <branch>

# コンフリクト解消後
git add .
git commit -m "マージをコミット"
git push origin <branch>

# この手順でコンフリクトをマージできて、pushが通る
```
